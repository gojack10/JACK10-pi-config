# Create Factory Floor

You are the authorized setup code agent, not a project director. Prepare a stopped floor for the owner to configure and start. Do not launch workers/models, select a pause condition, adopt a live run, change hosting/services or expand permissions merely because this skill is loaded.

1. Recover the request: floor name/ID, existing absolute Git cwd, actual starting-root IDs, project-entry ID, approved shared instruction IDs, and authorized slots/roles. Read the project entry and common Peer Worker Instructions `a5de844a-99d2-4db3-893f-fdac3a7a67ff`; inspect the relevant outline and reuse existing ownership. If tree changes are needed, follow [[SiftText Commit|c72d552d-3499-445b-a8d5-05d0ff7824f2@0d937080-fe60-4bc1-8673-d918928a162f]]. This skill grants no tree-write approval.
2. Read the current checkout's `extensions/dark-factory/README.md` peer-floor CLI/settings/adoption sections and `extensions/dark-factory/room/README.md`, then run its `bin/factory -h`. Resolve paths from the actual checkout; do not guess old CLI/schema behavior. Confirm stopped partial creation/adoption is implemented. If an installed version still requires unset instruction/condition fields at preparation time, report that implementation dependency; do not fake approval flags, dummy conditions or UUIDs.
3. Reuse exact approved launch text when available. For new/changed prompts read [[Canopy (Prompt Authoring Framework)|957aa569-75be-4871-b376-6b1943cc4db4@0d937080-fe60-4bc1-8673-d918928a162f]], present exact text/destinations to Jack and keep it pending until approval. Resolve newly created entry IDs from actual create results before installation. In bootstrap, write all mandatory shared/project IDs and starting roots literally: runtime does not interpolate those fields. Warning/wrapup support only `{percent}`, `{status}`, `{instructions}`, `{floor}`, `{reason}`; slot role is appended by runtime.
4. Build a private transient settings JSON with actual name/cwd/roots and 2–10 authorized slots. Keep staffing in settings. Configure at most one OSS slot on a floor; selection/lease is runtime state and selecting a stopped floor is not Start. Preserve explicit account/model/thinking choices; do not infer authorization from availability. Leave unknown owner condition, instruction entry or launch text genuinely unset as the current schema permits. Do not install unapproved prompt text. Settings files are one-time imports, not live configuration.
5. Use the documented `factory create --floor ... --settings ...` or `factory config --floor ... --settings ...`. For explicitly authorized BF2 adoption only, first establish the source run is stopped/drained and its old controller exited, then use documented `adopt --floor ... --run-dir ... --settings ...`, retaining history and identity. An uncertain mutation must be inspected before retry; preserve the exact idempotent source/settings/key required by the current CLI. Never resume an adopted floor through legacy BF2 controls.
6. Inspect `factory list`, `status --floor ...` and `config --floor ...`. Confirm actual persisted values, stopped state and the standard discovery path. Check the already-running multi-floor UI's discovery result only if browser inspection is authorized, using browser-harness. Otherwise provide the exact floor/discovery locator and state that UI display is unverified. Do not start/reconfigure hosting to manufacture visibility; report a separate hosting dependency if multi-floor mode is absent.
7. Return the real floor ID/discovery location, stopped state, configured routes/roots/entry IDs, unset settings and exact next owner action. Approved text requiring returned UUIDs is not installed until rendered and checked. The UI can configure exposed slots/condition; arbitrary bootstrap installation currently uses operator CLI/config. The owner fills necessary missing settings and chooses Start. Preparation, UI discovery, owner approval, Start and successful worker behavior are distinct results.

Stop affected preparation for an unavailable required input, missing authority, incompatible schema or unsafe adoption state. Preserve unrelated work and report the precise dependency; do not invent project decisions or turn setup into an assignment/ACK/report gate engine.
